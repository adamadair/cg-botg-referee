# Botters of the Galaxy Referee

A CodinGame Botters of the Galaxy Referee that can be used with automated testing programs like cgarena and Brutal Tester.

Content:
- Running a headless game
- League levels
- Balance notes multi
- Balance notes
- Bugs
- Unit stats
- Skill stats
- Item information
- Game loop
- Attacktime

## Running a headless game

Build the runnable jar (also compiles the sample `SimpleWaitBot` into `target/test-classes`):

```
mvn package
```

Then run a match between two bots, each given as the command line that starts it:

```
java -jar target/cg-botg-referee-1.0.jar \
    -p1 "java -cp target/test-classes SimpleWaitBot" \
    -p2 "python3 my_bot.py" \
    -league 7 -seed 1337 -l game.json
```

| Option | Description |
|--|--|
| `-p1 <cmd>` | Required. Command line for player 1. |
| `-p2 <cmd>` | Required. Command line for player 2. |
| `-league <n>` | League level, 1–7 (see below). Defaults to 7, the full game. |
| `-seed <n>` | Map/item seed. Random if omitted; the seed used is printed at the end. |
| `-l <file>` | Write the full game result (all frames, player stdout/stderr, summaries) as JSON. |
| `-s` | Start the web viewer server instead of running headless. |
| `-h` | Print help. |

In headless mode the runner prints one score per player (player 1 first), followed by the referee's initial data (e.g. `seed=1337`). A player that loses (tower destroyed, all heroes dead, timeout or invalid output) scores `-100000000`; otherwise the score is creep kills + denies, and the higher score wins at the end of the game.

## League levels

Each level adds one feature on top of the previous one. Level *n* uses the statement, stub and boss in `config/level<n>/`; the restrictions are applied by `Referee.setupLeague`.

| Level | League | Adds | Rules at this level |
|--|--|--|--|
| 1 | Wood 6 | Starting league | 1 hero, no lane units, no items, no skills, no bushes, no Groots; towers have half health and deal 1 damage; 200 rounds. |
| 2 | Wood 5 | Items | As level 1, plus buying and selling items. |
| 3 | Wood 4 | Lane units | As level 2, plus melee and ranged lane units; last hits give gold and you can deny your own units. |
| 4 | Wood 3 | Bushes, real towers | As level 3, plus bushes for hiding; towers deal 190 damage. |
| 5 | Wood 2 | Groots | As level 4, plus neutral Groot creatures; towers have full health. |
| 6 | Wood 1 | Second hero | As level 5, but each player controls 2 heroes. |
| 7 | Bronze and above | Skills | Full game: 2 heroes with 3 skills each, 250 rounds. |

## Using it with cgarena

[cgarena](https://github.com/adamadair/cgarena) plays many games between bots through a referee and reports wins, losses, draws and win rates. The jar works with it as is: cgarena adds `-p1`, `-p2`, `-seed` and, with `-l`, a per-game log path to the referee command, and the referee prints the score lines and `seed=` line cgarena expects.

### With flags

```
cgarena \
  -r "java -jar cg-botg-referee-1.0.jar" \
  -p1 "python3 my_bot.py" -pn1 MyBot \
  -p2 "python3 old_bot.py" -pn2 OldBot \
  -n 100 -t 4 -s -i 1000 \
  -l logs/run1 \
  -fault-pattern 'timeout|timed out|[Ii]nvalid|duplicate hero'
```

- `-s` swaps seats between games, so each map is played from both sides. `-n` must then be even.
- `-t` runs games in parallel. Each game starts its own JVM and two bots, so keep it at or below your CPU core count.
- `-l` keeps each game's JSON log (`match_<n>.json`), the referee's stderr (`match_<n>.err`) and a `games.jsonl` with one result per game. Open a `match_<n>.json` to see why a game ended.
- `-fault-pattern` marks a bot as faulted when the referee ends its game for a timeout or invalid output (bad hero name, unknown command, duplicate hero). Normal losses such as "Tower destroyed" or "All heroes dead" don't match it.
- The default per-game `-timeout` of 30s is plenty: a full game takes a few seconds.

### Choosing a league

cgarena splits the referee command on spaces, so add `-league` to it to play a lower league:

```
cgarena -r "java -jar cg-botg-referee-1.0.jar -league 3" -p1 "python3 my_bot.py" -p2 "python3 old_bot.py" -n 20 -s
```

Without `-league` the referee plays level 7, the full game.

cgarena doesn't support quotes in the referee command, so the path to the jar must not contain spaces. If it does, put the `java -jar ...` command in a small script and pass the script's path to `-r`. Player commands (`-p1`, `-p2`) may contain spaces; they are passed to the referee as single arguments.

### With a config file

`config.json`:

```json
{
  "referee": "java -jar cg-botg-referee-1.0.jar",
  "players": [
    { "name": "MyBot",  "cmd": "python3 my_bot.py" },
    { "name": "OldBot", "cmd": "python3 old_bot.py" }
  ],
  "games": 100,
  "threads": 4,
  "seed": 1000,
  "swap": true,
  "log_output": "logs/run1",
  "fault_pattern": "timeout|timed out|[Ii]nvalid|duplicate hero"
}
```

```
cgarena -config config.json -md summary.md -html summary.html
```

Flags given on the command line override the config file, for example `cgarena -config config.json -n 10 -l logs/quick`.

### How cgarena counts the results

- **Win / loss**: one bot has the higher score at the end, or the other bot was eliminated (`-100000000`).
- **Draw**: both bots have the same creep kills + denies after the last round.
- **Double forfeit**: both bots were eliminated in the same turn, so both scores are `-100000000`. Not counted in the win rate.
- **Invalid**: the referee failed, timed out or wrote a bad log. Not counted in the win rate; cgarena prints the reason.
